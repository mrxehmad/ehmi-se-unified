Fixing UEFI Shell Boot Issues on Chromebook with MrChromebox Firmware

Ehmad December 20, 2025 4 min read

If you’ve installed Debian 12 on your Chromebook using MrChromebox BIOS firmware and suddenly find yourself dropped into a UEFI shell instead of your operating system, don’t panic. This is a common issue that occurs when the UEFI firmware cannot locate the bootloader on your SSD.

The error message typically indicates that the system is “booting from SSD” and asking you to “verify it contains 64bit UEFI OS.” This guide will walk you through both a quick temporary fix to boot your system immediately and a permanent solution to prevent this from happening again.

Understanding the Problem

When you see the UEFI shell, it means that the firmware has successfully detected your SSD but cannot find or execute the bootloader. This usually happens because:

  • The boot entry in NVRAM has been lost or corrupted
  • The EFI partition is not properly configured
  • GRUB bootloader files are missing or misconfigured

Quick Temporary Fix: Manual Boot from UEFI Shell

This method will get you back into your Debian system right away without making any permanent changes.

Step 1: Identify Your Drive

In the UEFI shell, type the following command to list all available filesystems:

map

This will display a list of available drives. Look for your SSD, which is typically labeled as FS0: or FS1:. Make note of which filesystem corresponds to your installation drive.

Step 2: Navigate to Your Drive

Once you’ve identified your drive, navigate to it by typing:

FS0:

Replace FS0: with whatever identifier corresponds to your SSD from the previous step.

Step 3: Boot the System

Now execute the GRUB bootloader manually:

cd EFI\debian
grubx64.efi

This should immediately boot your Debian installation. However, this is only a temporary solution, and you’ll need to repeat these steps every time you restart unless you apply the permanent fix below.

Permanent Solution: Repair Boot Entry

Once you’ve successfully booted into Debian using the method above, follow these steps to permanently fix the boot configuration.

Step 1: Check Current Boot Entries

Open a terminal and run:

sudo efibootmgr -v

This command displays all boot entries stored in your system’s NVRAM. Review the output to see if a Debian entry exists and whether it’s pointing to the correct location.

Step 2: Reinstall GRUB

Reinstall GRUB to recreate the proper boot entry:

sudo grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=debian

This command installs the GRUB bootloader to your EFI partition and creates a new boot entry in NVRAM.

Step 3: Update GRUB Configuration

After reinstalling GRUB, update its configuration:

sudo update-grub

This regenerates the GRUB configuration file with all available operating systems and kernel versions.

Step 4: Reboot and Test

Restart your system to verify that it now boots correctly:

sudo reboot

Your Chromebook should now boot directly into Debian without dropping into the UEFI shell.

Troubleshooting: EFI Partition Issues

If the above steps don’t resolve your issue, the problem might be with your EFI partition mounting.

Check if EFI Partition is Mounted

Run this command to check if your EFI partition is properly mounted:

mount | grep efi

If you don’t see any output, your EFI partition is not mounted.

Mount the EFI Partition

Identify your EFI partition (usually the first partition on your drive):

sudo fdisk -l

Look for a small partition (typically 100-500MB) with type “EFI System.”

Mount it manually:

sudo mount /dev/sda1 /boot/efi

Note: Replace /dev/sda1 with your actual EFI partition identifier from the fdisk output.

Retry GRUB Installation

Now that the EFI partition is mounted, repeat the GRUB installation steps:

sudo grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=debian
sudo update-grub

Prevention: Make EFI Partition Mount Permanent

To ensure your EFI partition always mounts at boot, verify it’s in your /etc/fstab file:

cat /etc/fstab | grep efi

If there’s no entry, add one by editing the fstab file:

sudo nano /etc/fstab

Add a line similar to:

UUID=XXXX-XXXX  /boot/efi  vfat  umask=0077  0  1

Replace XXXX-XXXX with your EFI partition’s UUID, which you can find using:

sudo blkid | grep vfat

Conclusion

The UEFI shell issue on Chromebooks running MrChromebox firmware is typically caused by missing or corrupted boot entries. By manually booting through the UEFI shell and then reinstalling GRUB from within Debian, you can restore proper boot functionality.

If you continue experiencing issues after following this guide, consider checking the MrChromebox community forums or the Chromebook-specific Linux communities for additional support related to your specific Chromebook model.
