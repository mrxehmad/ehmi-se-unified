Local Hostname Resolution Setup  `h1.ehmi.se`

Ehmad April 26, 2026 3 min read

Router: OpenWrt (homerouter)
Date: April 2026

Overview

The goal was to resolve local hostnames in the format {hostname}.h1.ehmi.se across the network (e.g. auron.h1.ehmi.se → 10.1.0.2). This was incorrectly referred to as “mDNS” but is actually local unicast DNS resolution using the existing DNS infrastructure.

Network Topology

Client
  └──▶ Pihole (10.1.1.5)          — primary DNS, ad blocking
         └──▶ AdGuard (10.1.1.2)  — secondary DNS
               └──▶ dnsmasq (10.1.1.1) — router, knows all local hosts
                     └──▶ Internet (upstream)

Subnets

DNS Servers

ServerIPRole
dnsmasq10.1.1.1Router DNS, knows local hosts

Problem

Clients could not resolve local hostnames like auron.h1.ehmi.se. All DNS traffic was hijacked by a firewall rule to go to Pihole, but Pihole had no knowledge of local hosts.

Changes Made

1. OpenWrt — dnsmasq (/etc/config/dhcp)

Configured dnsmasq to serve the h1.ehmi.se domain and auto-expand hostnames from existing DHCP host entries.

uci set dhcp.@dnsmasq[0].local='/h1.ehmi.se/'
uci set dhcp.@dnsmasq[0].domain='h1.ehmi.se'
uci commit dhcp
service dnsmasq restart

Effect: dnsmasq now answers auron.h1.ehmi.se → 10.1.0.2 automatically from the static host entries already defined in /etc/config/dhcp.

2. Pihole — Conditional Forwarding

Told Pihole to forward all h1.ehmi.se queries to dnsmasq on the router instead of trying to resolve them itself.

Location: Pihole Admin → Settings → DNS → Advanced → Reverse servers

true,10.1.0.0/24,10.1.1.1,h1.ehmi.se

Effect: Pihole now correctly returns 10.1.0.2 for auron.h1.ehmi.se instead of returning its own IP (10.1.1.5).

3. AdGuard — Upstream DNS Rule

Told AdGuard to forward all h1.ehmi.se queries to dnsmasq on the router.

Location: AdGuard Admin → Settings → DNS settings → Upstream DNS servers

[/h1.ehmi.se/]10.1.1.1

Effect: AdGuard now correctly returns 10.1.0.2 for auron.h1.ehmi.se.

Verification

All three DNS servers now return the correct answer:

nslookup auron.h1.ehmi.se 10.1.1.1   →  10.1.0.2  ✅  (dnsmasq)
nslookup auron.h1.ehmi.se 10.1.1.5   →  10.1.0.2  ✅  (Pihole)
nslookup auron.h1.ehmi.se 10.1.1.2   →  10.1.0.2  ✅  (AdGuard)
nslookup auron.h1.ehmi.se            →  10.1.0.2  ✅  (default DNS)

How It Works (Flow)

Client asks: "where is auron.h1.ehmi.se?"
        ↓
DNS Hijack firewall rule → Pihole (10.1.1.5)
        ↓
Pihole: "h1.ehmi.se is forwarded to 10.1.1.1"
        ↓
dnsmasq on router: "auron is in my host list → 10.1.0.2"
        ↓
Client gets: 10.1.0.2 ✅

What This Is NOT

This setup is not mDNS. The differences:

FeaturemDNSThis setup
ProtocolMulticast UDPUnicast DNS
Domain.local onlyh1.ehmi.se (custom)
Crosses VLANs❌ No✅ Yes
Needs server❌ No (peer to peer)✅ Yes (dnsmasq)
Works herePartial (same subnet only)✅ Fully working

Notes

  • The DNS hijack firewall rule (DNAT on port 53) forces all clients to use Pihole regardless of their configured DNS. This is why both Pihole and AdGuard needed to be configured — depending on which server a query reaches first, it must know to forward h1.ehmi.se to dnsmasq.
  • No changes were needed to client devices.
  • Adding new hosts to /etc/config/dhcp on the router will automatically make them resolvable as {name}.h1.ehmi.se with no further changes needed.
